# Day 6 Data Note

## Source Posture

All seed data is **manually authored and calibrated**. No programmatic scraping was performed.

dm8.in and similar portals were used as **visual references only** to calibrate realistic:
- society names and builder names for Bengaluru
- price/sqft ranges per micro-market
- typical floor counts, BHK distributions, and maintenance cost ranges
- area-specific externalities and infrastructure signals

No data was extracted programmatically. Every JSON record was hand-authored.

---

## What Each File Contains

### `data/seed/properties.json`
20 property records across 5 Bengaluru micro-markets:
- Whitefield (4 properties)
- Sarjapur Road (4 properties)
- Bellandur (4 properties)
- HSR Layout (4 properties)
- North Bengaluru / Hebbal / Yelahanka (4 properties)

### `data/seed/area_profiles.json`
5 area profiles covering: Whitefield, Sarjapur Road, Bellandur, HSR Layout, North Bengaluru.

### `data/seed/societies.json`
12 society/project profiles referenced by the 20 properties.

## Key Assumptions

1. **All properties are resale ready-to-move** in the seed set — this simplifies the first UI iteration. Under-construction properties will be added later with more realistic possession timelines.

2. **`match` fields are intentionally absent** from seed data. `match.score`, `match.breakdown`, and `match.explanation` are runtime outputs from the ranking engine — they do not belong in the seed JSON.

3. **`transparency_tags` in seed data are placeholders** for the first UI. Eventually these will be computed at query time from property scores + area stats. For now they are hand-set to enable UI development.

4. **Images are placeholder URIs** in the format `placeholder://property-id/image-name.jpg`. The frontend should handle missing images gracefully from day one.

5. **`area_id` and `society_id` are foreign keys** — the backend must join these at query time to compose the full property detail page response.
